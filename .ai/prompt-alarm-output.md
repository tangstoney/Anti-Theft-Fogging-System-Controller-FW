本轮目标是报警开始后本机语音循环、有源蜂鸣器响、红蓝 LED 交替闪烁，报警停止后关闭三路输出。保持现有 RT-Thread 3.1.4 与 Arm GCC 构建方式。先检查工作区已有修改，复用当前驱动和接口，直接完成实现与实际构建。

## 接入当前工程

当前 app/rd91_types.h 已有 Rd91Sink.alarm_output，src/main.c 有 alarm_output_sink，app/rd91_app.c 有 alarm_start/alarm_clear。优先沿用这些入口，把输出桩接到真实驱动。app/ 继续使用普通 C，业务状态由 main 线程单点维护。状态机满足报警条件后发出本地输出请求，驱动负责执行该请求。

如果当前运行路径还没启用完整业务状态机，提供一个明确标记的 BENCH 自检入口，直接测试本地声光服务的开始和停止。入口用现有台架按键、已有测试接口或调试器可调用函数，选改动最小且可重复验证的方式。正常启动时输出关闭，自检入口由编译配置启用。README 写明如何操作和退出。

用一个静态分配的声光服务线程拥有三路输出。通知只唤醒线程，当前期望输出状态和版本才是依据。连续 START 幂等，重复 STOP 幂等。开始后立即收到停止、快速开始/停止、停止后再次开始，都要收敛到最新状态。三路输出回调可合并唤醒，但需要保证最后的 STOP 不因队列满或旧 START 而失效。线程无事可做时阻塞等待，有闪灯或发送时序待完成时按期限等待。

## 语音芯片

这份 WT588F02-8S-C 手册给出的播放控制是一线或两线 GPIO 时序，手册提到的 BUSY 9600 波特率返回工程信息属于另一功能。按第 6.2 节及到手芯片已烧写的控制模式实现播放控制。

若控制模式尚未确认，可先以两线模式作为明确标记的台架默认实现，并把实际芯片模式列为上板前需要确认的配置。源码集中配置模式、语音段地址、单/双字节格式、音量、DATA/CLK/BUSY GPIO 和有效电平，音频资源已在 WT 芯片内，段号需对应实际烧写内容。

两线模式用手册时序，核对上电约 40ms 初始化时间、发码前的电平准备、5ms 起始信号、LSB-first 位序、字节顺序、时钟范围和最小命令间隔。播放某段后再发 F2 循环，停止用 FE，双字节使用对应完整命令。循环命令在开始阶段发一次，重复 START 保持当前播放。BUSY 接入时区分已发命令、检测到播放与播放故障，设置有限等待并记录异常。

播放控制为低频操作，首版允许在线程中用 GPIO 模拟两线时序，并在连续数据位发送期间用 rt_enter_critical()/rt_exit_critical() 锁调度。当前 RTT3.1.4 的这两个接口保留中断响应，UART 接收和系统 tick 可继续服务。微秒延时使用独立且可校验的时基，例如自由运行硬件计数器或 DWT，按实际系统时钟换算。锁调度期间只进行 GPIO 和有界微秒延时，日志、阻塞 IPC 和 rt_thread_delay 放在锁外。上电等待、发码准备和命令间隔在时序允许处让出 CPU，保留 RTT 对 SysTick 的所有权。单字节的八个数据位按高低电平各350us估算约5.6ms，双字节约11.2ms；用实测记录调度推迟和脉宽。逻辑分析仪在 IMU 运行及后续 UART RX 活跃时验证整个位周期仍在手册200us～3.2ms范围内，同时核对数据建立保持时间。若中断拉长脉冲超过容差或业务线程时延超标，再改为硬件定时器推进边沿。整条命令保持全局中断屏蔽会延迟 UART 和 tick，本轮选锁调度并保留中断的方式。每次完整命令之后检查最新停止请求，开始和循环命令之间允许处理取消，记录最坏停止延迟。

GPIO 上电电平按手册处理，特别是 IO2 上电不得被上拉。WT 若以 5V 供电，手册 VIH=0.8VCC，要根据实际电路确认 3.3V 控制信号及 BUSY 回读电平匹配。外接功放的使能与音频连接按硬件实际设计配置。

## 蜂鸣器和红蓝灯

蜂鸣器资料型号 GPD4216L100-3-36V2800 是内含驱动电路的有源蜂鸣器。由 MCU GPIO 控制外部驱动级使其通断，按实际电源、MOS/三极管和使能极性接入。上电关闭，报警期间先持续响，停止时关闭。其标称最大电流 35mA，供电通过驱动电路接入。记录手册为至少 100dB@10cm，与产品声压验收要求的差异。

红蓝灯默认每 250ms 切换一次，作为可配置的演示值。报警期间红亮蓝灭、红灭蓝亮交替，停止时两路关闭。灯的有效电平和 GPIO 集中在板级配置，接入时核对双色灯是三脚共阳/共阴还是两脚反并联，再采用匹配的驱动方式。

核对现有 IMU、按键、台架 LED、console、SWD 及未来 BLE UART4/控制脚的占用后，选择空闲且在开发板排针上可接出的 GPIO。输出接线表，列 MCU 脚、排针、有效电平、电压和驱动级。台架按键自检与报警灯要有明确输出所有权，避免两个线程操作同一个灯。声光任何一项故障都要记录，各通道能继续执行有效的停止操作。

## 与未来通信线程的关系

未来通信线程独占 UART4、AT 命令和解析。本轮把本地声光入口做清楚，保留以后发布 alarmNotify 的接点即可，具体命名复用现有风格。

未来多个接收者订阅时，每个接收者要有自己的通知或待处理记录，避免多个线程竞争消费同一个事件位或同一个队列消息。RTT 的事件位清除与消息队列接收语义都要按实际内核版本核对。

现有 fog_send 表达业务已批准的烟罐请求。保留它与本地报警的独立语义，通信侧未来只发送已经生成的业务请求及其请求号。当前代码里拖车分支只做声光，这类分支仍按原规则运行。报警快照可带版本号供未来订阅者同步当前状态，烟罐请求保留逐条交付与回执语义。

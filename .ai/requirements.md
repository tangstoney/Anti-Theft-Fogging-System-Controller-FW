## 冲突与待确认规则

| ID | 问题 | 需要谁/什么证据 | 台架推进方式 |
|---|---|---|---|
| Q01 已解决 | 出厂默认撤防 | 唐石2026-11-11明确确认 | 按撤防实现；普通重启持久化恢复仍需另定义 |
| Q02 接线口径已定 | 旧图TI引脚编号忽略 | 唐石2026-11-11确认 | 开发板沿用N32例程；量产三板BOM/原理图后续对接 |
| Q03 | P1 主机↔烟罐写 2.4G，H1 写 BLE；2.4GHz 频段不等于专有 RF 能力 | 无线方案与供应商能力确认 | 后续 BLE 只作台架传输，保持业务/传输分离 |
| Q04 | 中控要连钥匙、烟罐、手机；现有 AT 例程只有单连接环境和单对端配置 | 供应商确认连接数/主从并发/固件版本，实测 | 先分别验收两板链路；不能直接承诺三板同时 BLE 联通 |
| Q05 | 冲击/拖车/行驶阈值、双 IMU 融合、Context 能力不完整 | 产品+算法/模块供应商，采样数据 | 驱动读取和明确模拟事件，不能编造识别率 |
| Q06 已解决 | 雷达以实际厂家资料为准 | 唐石2026-11-11确认；觅感规格书 | 按OUT/UART接入；不采用旧图SPI |
| Q07 | WT588F02 语音接口与旧图 I2C/I2S 标注不一致 | 实际语音芯片型号、控制模式与资料 | 不假设语音芯片支持 I2C/I2S；先占位接口 |
| Q08 | 执行 ACK 是已接收/已接受/开始动作/完成/物理喷烟成功？ | 产品+硬件定义反馈信号 | LED 模拟 ACK 不宣称真实喷烟成功 |
| Q09 | 喷烟不可逆，重试、去重、掉电后防重复、撤销边界 | 产品+硬件共同定义 | 不自动重发执行；取消声光不等于撤回已执行喷烟 |
| Q10 | 遥控触发在撤防/行驶中是否仍禁用、授权 ID 对砸车分支是否豁免 | 产品给出优先级矩阵 | 保持静停/撤防禁执行约束，不添加例外 |
| Q11 | 低电阈值、串并联电池、过期数据、模块掉线如何处理 | 原理图+电源规格+产品规则 | 电量未知不伪造 100%；断链不当作成功 |
| Q12 | 配对绑定数、密钥下发/更换、鉴权、防重放、读保护 | 产品/安全/供应商接口 | 无配对 demo 仅台架，安全功能未完成 |
| Q13 | 开发板型号/PCB版本/引脚有效电平/M0镜像 | 到手板照片、原理图、AT+INFO? | 记录并更新 board.md，保留原型与产品两套表 |

P1 §7.1 的“喷烟启动延迟 1s、报警30分钟”同时说明 DVT 前最终标定，当前不把这两个数作为最终验收指标。后续彩屏视频、继电器、4G、GPS、指纹、人脸保留扩展任务，不纳入首轮工程。
